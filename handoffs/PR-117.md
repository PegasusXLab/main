# Handoff: PR-117 / T-147
## Builder notes
Built by senior (acting as builder) after Quang revived T-147 (~00:30 EDT). Branch `feat/T-147-email-verification`, commit a31cd284.
### What changed
- **Register:** creates an UNVERIFIED account, emails a 6-digit code, and answers 202 with no session.
- **New routes:** `/api/auth/verify` (the right code signs you in) and `/api/auth/verify/resend` (1 per minute, 5 per hour).
- **Login on an unverified account:** answers 403 needsVerification. The form opens the code step and sends a fresh code.
- **Existing accounts** (no flag) count as verified.
- **Codes:** stored only as an HMAC keyed with AUTH_SECRET; 10 minutes, 5 tries.
- **Abuse limits:** sign-up 5 per IP per 10 minutes (well-formed attempts only), plus a honeypot field.
- **Mail:** nodemailer 10.0.10 over Gmail SMTP 465. Without the Gmail variables it prints to the console outside production and answers 503 in production.
- **Test hook:** a request whose `x-e2e-verify-secret` header equals env `E2E_VERIFY_SECRET` (24+ chars) gets `testCode` back. `playwright.config.ts` sets a local default; live runs must export the Vercel value.
### Gotchas
- R3F/Next aren't involved. The sign-up limit is per serverless instance, so it's a soft limit.
- Repeated local e2e runs WITHOUT the header use up the 5-per-10-minutes allowance. All e2e helpers send the header.

### How to test
1. **Preview, real inbox:**
   - Register and check that the email "Your Galleriverse code: NNNNNN" arrives.
   - A wrong code shows "4 tries left"; the right code takes you to the editor.
   - Log out and log back in, which should work.
2. **Unverified login:** register a second account, close the tab before entering the code, then log in. The code step should open, and a new code should arrive (or "Wait Ns" if under 60 s).
3. **Automated:** `E2E_BASE_URL=<preview> E2E_VERIFY_SECRET=<vercel value> npx playwright test tests/e2e/auth.spec.ts tests/e2e/auth-session.spec.ts --project=chromium`
