## How the capture pipeline works (and its traps)
- `capture/lib.mjs` swaps rAF/performance.now/Date.now for a **virtual clock**: every frame is
  exactly 1/30 s, independent of render speed. `rec.freeze()` → `rec.run(sec, fn)` records.
- `capture-hero.mjs <viewUrl> <plan.json> <name>` + `hero-<name>.mjs`: art-aimed pans from a
  plan (camera arrival pose + bearing to each frame/object). Plans come from the app's own compile
  code via a throwaway vitest file in `pegasus-code/src/viewer3d/zz-plan.test.ts` (delete after!).
- Traps already hit: artwork `aspect` = **height / width**; TourView ignores a click that follows
  a drag (send a keydown first); fonts must load **before** freezing the clock (lib does this);
  macOS has no `timeout` command; Remotion's bundled ffmpeg only writes to paths inside the video
  project and lacks some filters; headless e2e renders a few fps (hold keys with repeated keydowns).
- Dev server for captures: `cd pegasus-code && npm run dev` (:3000). Local galleries are seeded by
  `capture/seed-*.mjs` and `galleries/build.mjs`.
