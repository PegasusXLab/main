## Goal
A creator types a mood ("quiet rainy afternoon"). Gemini picks a kit, an accent color and an overlay intensity and explains why in one sentence. The result applies live and is undoable. Serves: Gemini side challenge (visible sponsor use) + Creative track.
## Acceptance criteria
- [ ] `src/app/api/mood/route.ts` (POST, server only). Read node_modules/next/dist/docs first (AGENTS.md gotcha). zod input `{ roomName ≤80, roomDescription ≤500, mood 1–200 chars }`; 400 on bad input.
- [ ] Calls `POST https://generativelanguage.googleapis.com/v1beta/models/${GEMINI_MODEL}:generateContent` with header `x-goog-api-key` = `process.env.GEMINI_API_KEY`, `generationConfig.responseMimeType: "application/json"` + a response schema (confirm `responseSchema` vs `responseJsonSchema` in Google's live docs at build time) returning `{ kitId: enum(KIT ids), accentColor: string, overlayIntensity: number, reason: string }`. Default model `gemini-3.5-flash-lite`; env `GEMINI_MODEL` overrides.
- [ ] Server-side validation: kitId ∈ KITS; accent matches `^#[0-9a-fA-F]{6}$` else the kit default; intensity clamped 0–1; reason ≤160 chars, markup stripped. Anything invalid → keyword fallback (`KITS[].keywords`, default `gallery`).
- [ ] 8 s AbortController timeout, 1 retry, then fallback. Missing key → fallback (never a 500). Response `{ kitId, accentColor, overlayIntensity, reason, source: "gemini" | "cache" | "demo" | "fallback" }`.
- [ ] In-memory cache keyed by `mood.trim().toLowerCase() + "|" + kitIds.join(",")`. `src/lib/mood/demoCache.json` holds 3 pre-generated real Gemini responses for the demo phrases (generated by the builder with the real key, committed) and is checked first, so the live demo never depends on the network.
- [ ] Privacy: only room name/description + mood are sent; nothing user-typed is logged (log only source + latency). The key never reaches the client bundle (reviewer greps `.next/static` for the key name).
- [ ] UI `src/panels/MoodField.tsx` under the kit chips: "Describe the mood" input + button, spinner; on result calls `applyKit(roomId, kitId, { accentColor, overlayIntensity })`, shows the reason with a small "✦ Gemini" tag. Fallback shows "Couldn't read the mood, so we picked <Kit>". Never a raw error. Also stores the typed mood in the existing `room.mood` field in the same `updateRoom` (one undo).
- [ ] Tests: route with fetch mocked (ok, malformed JSON, bad enum, timeout → retry → fallback, no key); pure validate/fallback fns; MoodField component. `.env.example` gains `GEMINI_API_KEY=` and `GEMINI_MODEL=` (names only).
- [ ] Ticket log records the exact endpoint, model and feature (structured output) for the submission tech list. Handoff notes: free-tier limits are per project, visible only in AI Studio; RPD resets at midnight PT.
