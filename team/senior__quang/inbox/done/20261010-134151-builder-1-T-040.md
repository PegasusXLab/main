BUG (found by Vic during testing): image upload fails in Safari with 'Invalid file format: must be valid WebP image with magic bytes', for ANY file. Root cause: src/upload/resizeImage.ts defaultRenderWebP uses canvas.toBlob(..., 'image/webp'); Safari can't encode WebP from a canvas and silently returns PNG, and the client never checks blob.type, so /api/upload (isWebP) rejects it. Chrome/Edge/Firefox work. Proposed fix, one small PR: (1) client: if blob.type !== 'image/webp', re-encode as image/jpeg 0.85 (+1 test); (2) server /api/upload: accept JPEG (FF D8 FF) and PNG (89 50 4E 47) by magic bytes too, store with the matching content type and extension (.jpg/.png), keep the size caps and magic-bytes rule (+tests). WebP stays preferred (ADR-009 note). It touches builder-2's resizeImage.ts and my upload route. Please create a bugfix card (assign me both files, or split per lane). I'll start the moment it lands.
