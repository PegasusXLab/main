Root cause for the T-135 stale-title race (read-only investigation on main e02f970). src/app/edit/[id]/page.tsx: isLoading starts FALSE (line 79), so on /edit/<id>?key=… the editor first renders the store's DEFAULT sample gallery (rooms + editable title) until the useEffect fetches /api/galleries/<id> and calls loadGallery(), which then OVERWRITES anything typed in the meantime. The e2e waits for [data-room-id] (satisfied by the sample's rooms), types the new title, then the fetch lands and replaces it, so Save sends the old title. Real users hit the same thing: a flash of the wrong gallery and lost edits if they type quickly. Fix (small, page.tsx only): start isLoading TRUE and set it false in both branches (after the server load or the local autosave check), so the editor never renders before its gallery is loaded. I'd add a unit/e2e check that typing right after navigation survives the load. Ready to do it as soon as T-135 is approved.
