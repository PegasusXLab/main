Security note (non-blocking, already merged in T-102 / PR #68): src/lib/auth/ownership.ts stores editUrl WITH the plain edit key in the private owner index users/galleries/<userId>.json (recordGalleryOwner from POST /api/galleries). That contradicts T-031 ('only the hash is stored') and ADR-014 (the owner edits without the key). Private objects, so not exposed, but anyone with storage read access gets every key. Suggested post-freeze fix: store editUrl without the key and let the owner session authorize PUT (per ADR-014), or drop editUrl from the index. Your call whether it needs a card before 18:00.
